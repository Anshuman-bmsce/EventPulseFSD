# EventPulse — PDF Assignment Submission Platform

EventPulse is a local-first, event-driven student assignment submission application. A student selects an assignment, uploads a PDF and submits it. The backend validates the file, stores it in FLOCI's Google Cloud Storage emulator, publishes an `assignment_submitted` event to FLOCI Pub/Sub, and processes the message into FLOCI Firestore.

The frontend shows the final backend outcome to the student: **successful**, **duplicate**, **failed**, or **rejected**. Dashboard metrics are loaded from Firestore records, not generated by frontend buttons.

## Architecture

```text
Student browser
    |
    | multipart/form-data: student + assignment + PDF
    v
Express API (backend)
    |  1. Check file name, MIME type, PDF signature and 10 MB limit
    |  2. Store PDF object
    v
FLOCI Google Cloud Storage emulator (port 4588)
    |
    |  3. Publish assignment_submitted event
    v
FLOCI Pub/Sub topic: eventpulse-events
    |
    |  4. Subscriber validates and processes (max 3 attempts)
    v
Firestore transaction
    |-- processed_events       (event-ID idempotency)
    |-- student_submissions    (one successful submission per student + assignment)
    |-- duplicate_events       (repeat submission attempts)
    |-- failed_events          (failure/rejection quarantine)
    |-- submission_requests    (student-facing status/notification)
    v
Student notification + live dashboard metrics
```

## Requirements

- Docker Desktop with Docker Compose
- Internet connection for the first image/package download
- No separate Node.js or npm installation is needed for Docker mode

## Run locally

Open PowerShell in this project folder and run:

```powershell
docker compose up --build
```

Open these addresses:

- Student portal and dashboard: http://localhost:5173
- Backend health: http://localhost:8081/health
- FLOCI emulator: http://localhost:4588

The first run downloads container images and npm dependencies. Leave the PowerShell window and Docker Desktop running while testing. Stop the stack with `Ctrl+C`, or from another PowerShell window run `docker compose down`.

## Student workflow

1. Enter a student ID and name.
2. Choose one of the assignment cards.
3. Attach a `.pdf` file (maximum 10 MB).
4. Click **Submit assignment**.
5. The student portal waits for the Pub/Sub consumer's final status and shows the notification.

PDF checks are performed in both the browser and backend. The backend does not trust the file extension or browser MIME type alone: it also checks the file's `%PDF-` signature. Only PDF files are accepted.

## Event and idempotency behavior

- Each valid submission attempt receives a new event ID and is published to Pub/Sub.
- The Firestore transaction checks `processed_events/{event_id}` first. A Pub/Sub redelivery with the same event ID is acknowledged without repeating writes.
- It then checks the successful submission key `{student_id}__{activity_id}`. If a successful submission already exists for that student and assignment, the new event is recorded in `duplicate_events`, marked `duplicate` in `submission_requests`, and does not replace the original submission.
- A previous failed/rejected processing attempt does not create a successful submission record; the student may upload again.
- A new successful submission updates `student_submissions`, `student_activities`, `processed_events`, and `submission_requests` atomically.
- Retryable processing errors are retried up to `MAX_RETRIES` (default 3). Exhausted failures are stored in `failed_events`, and the student gets a failure notification.
- Invalid event payloads are rejected and quarantined rather than retried indefinitely.

## FLOCI integration

The Compose stack uses `floci/floci-gcp:latest` on port `4588`. The backend configures the supported Google Cloud SDKs through:

- `PUBSUB_EMULATOR_HOST=floci-gcp:4588`
- `FIRESTORE_EMULATOR_HOST=floci-gcp:4588`
- `STORAGE_EMULATOR_HOST=http://floci-gcp:4588`

FLOCI provides local emulation for Pub/Sub, Firestore and Cloud Storage through its GCP emulator. Data is persisted under `./floci-data` on the host. See the [FLOCI GCP emulator documentation](https://github.com/floci-io/floci-gcp) for service coverage and configuration.

Useful commands:

```powershell
docker compose ps
docker compose logs floci-gcp
docker compose logs backend
docker compose logs frontend
docker compose down
```

## Automated checks

From the `backend` folder, run:

```powershell
npm test
```

The included Node.js tests check PDF event schema validation, student-plus-assignment duplicate prevention, original-submission preservation, and Pub/Sub redelivery idempotency. These are logic tests using a small in-memory Firestore test double; they do not replace an end-to-end test against a running FLOCI container.

## Useful API routes

- `GET /health` — backend health and emulator mode
- `GET /api/assignments` — assignment list
- `POST /api/submissions` — multipart PDF submission producer
- `GET /api/submissions` — recent student-facing requests and statuses
- `GET /api/submissions/:eventId` — poll final processing status/notification
- `GET /api/activities` — student activity records
- `GET /api/events` — processed, failed and duplicate event traces
- `GET /api/stats` — dashboard counters
- `POST /api/test/temporary-failure` — instructor/demo-only retry path
- `POST /api/test/permanent-failure` — instructor/demo-only exhausted retry path
- `POST /api/test/malformed` — instructor/demo-only schema rejection path

## Demonstration checklist

1. **Success:** submit a valid PDF for a student and assignment. Verify the status becomes Successful, one `student_submissions` record is stored, and the processed count increases.
2. **Duplicate:** submit another PDF with the same student ID and assignment. Verify the student receives a Duplicate notification, `duplicate_events` increments, and the original successful submission remains unchanged.
3. **PDF rejection:** try a `.docx`, `.png`, a renamed non-PDF file, or a file larger than 10 MB. Verify it is rejected before a Pub/Sub event is published.
4. **Transient failure:** call `POST /api/test/temporary-failure`. It fails twice, succeeds on the third attempt and writes retry logs.
5. **Exhausted failure:** call `POST /api/test/permanent-failure`. It is retried up to the maximum and then written to `failed_events`.
6. **Malformed event:** call `POST /api/test/malformed`. Verify it is rejected and quarantined.
7. Capture Docker logs and dashboard screenshots as project evidence.

## Local emulator vs real cloud

This repository demonstrates the application using FLOCI's local GCP emulator. It is **not a deployed Google Cloud production service**. FLOCI data and local Docker logs are not proof of a live Cloud Run deployment or production Cloud Logging pipeline.

The demo currently uses a typed student ID instead of authenticated student accounts. For a public/production deployment, add identity verification (for example Firebase Authentication), enforce authorization on every student-specific record, scan uploaded PDFs for malware, set a retention policy, use least-privilege IAM, apply rate limits, and deploy Pub/Sub/Firestore/Cloud Storage resources in a real Google Cloud project. Do not expose this local demo as an unrestricted public upload endpoint.


## Separate student and admin interfaces

- Student view: enter a student ID and name, submit a PDF, and view only that student's own submission notifications/history.
- Admin view: choose **Admin** and enter the configured admin ID to view all submissions, aggregate metrics, processed events, duplicates and failed/rejected records.
- Demo admin ID: `EP-ADMIN-2026` (set `EVENTPULSE_ADMIN_ID` in `docker-compose.yml` before starting the stack to change it).
- Admin API routes require the `x-admin-id` header. Student history is scoped to the supplied student ID, and individual status lookups verify the matching student ID.

**Security note:** this is a classroom/demo access gate, not production-grade identity management. In production, replace the shared admin ID and typed student IDs with authenticated accounts, role claims, and server-side authorization.
